[2] IS ANY OF THIS DIFFERENCE REAL
    95% bootstrap confidence intervals, 2000 resamples of the test set.
    Two models are distinguishable only if their intervals barely overlap.

    best on test            Naive Bayes on tfidf
                            macro-F1 0.544   95% CI [0.452, 0.630]
    runner-up               Logistic Regression on tfidf
                            macro-F1 0.531   95% CI [0.437, 0.623]
    selected on validation  Linear SVM on fasttext
                            macro-F1 0.416   95% CI [0.327, 0.506]

    The best model's interval is 18 points wide. Every model in [1]
    falls inside it, so the leaderboard order is not established by its
    own numbers. Whether any pair of them differs needs a paired test,
    which compares the two models sentence by sentence rather than
    comparing two summary scores.

    McNemar, exact - is the leaderboard order real
      Naive Bayes+tfidf vs Logistic Regression+tfidf
      both right  56   only the first  10   only the second   8   both wrong  46
      p = 0.815   no measurable difference

    McNemar, exact - what did selecting on validation cost
      Naive Bayes+tfidf vs Linear SVM+fasttext
      both right  41   only the first  25   only the second  11   both wrong  43
      p = 0.029   difference survives

    Two different answers, and both matter:
    - The top of the leaderboard is flat (p = 0.815). Naive Bayes,
      Logistic Regression and the LSTM are one result, not a ranking.
    - The validation-selected model really is worse (p = 0.029), so
      the selection failure in [3] cost us something measurable.

    One caution on that second p-value: the model it favours was chosen
    because it topped the test set. Across 42 models the best-looking
    comparison is expected to look good, and 0.029 x 10 comparisons
    from [1] is no longer significant. We report it as suggestive.

[7] THE CEILING
    Macro-F1 of one annotator's labels predicting their partner's, on
    the same three classes and the same scale as every model score.

    pair    annotators              sentences   macro-F1
    pair1   Bath / Nacc                   200      0.438
    pair2   Nita / Reaksa                 200      0.608
    pair3   Seth / Krisna                 200      0.946
    all                                   600      0.666

    best model on test : 0.544
    human vs human     : 0.666
    gap                : +0.122

    The pairs differ more from each other than the model differs from
    the humans. Pair 3 shows the task is learnable when the guideline
    is applied consistently; pair 1 shows what happens when it is not.
    The label noise from the weaker pairs is in the training data, so
    the model inherits it.


[8] CONCLUSION
    1. The system works, weakly. 0.544 macro-F1 against a 0.333
       random baseline is real signal on a three-class problem.
    2. The top of the leaderboard is one result, not a ranking. McNemar
       cannot separate the best model from the runner-up (p = 0.815) and
       every model in [1] sits inside the best one's confidence interval.
       Reporting a single winner would be reporting noise.
    3. Choosing the model on 72 validation sentences cost real points:
       0.416 against 0.544, and validation rank barely
       correlates with test rank (rho -0.016). Cross-validation was the
       better selector (rho +0.389) and we should have trusted it.
    4. The bottleneck is the labels, not the algorithm. Our annotators
       score 0.666 against each other, and the model reaches 0.544
       against labels built from them. Most of the remaining gap is
       disagreement we baked into the data.
    5. Complexity did not pay at this size. TF-IDF with a linear model
       matches everything else, and the LSTM - the only model that reads
       word order - lands inside the same flat group despite costing far
       more to train.


[9] LIMITATIONS
    - 120 test sentences. Every number here carries roughly a
      +/-0.09 confidence interval, which is wider than most of the gaps
      we are comparing.
    - Trained on the resolved variant, where 199 of 600 labels came from
      the corpus rather than from our annotators. The agreement-only
      variant has not been run through the models, so the robustness
      check the annotation report promises is still open.
    - Single train/val/test split with one seed. Repeated splits would
      give a better estimate than one 120-sentence test set.
    - Segmentation is unvalidated: no gold segmented Khmer to check the
      CRF against, so tokenisation errors propagate silently.


[10] WHAT WOULD ACTUALLY IMPROVE IT
    In the order we would do it:
    1. Re-annotate pair 1 and pair 2 with the tightened guideline. Pair 3
       reached 0.917 Kappa, so the ceiling moves before any model changes.
    2. More data. 408 training sentences is the binding constraint on
       every model, and the only one that helps the RNN.
    3. A pretrained Khmer language model (XLM-R, or a Khmer BERT) instead
       of embeddings trained on 408 sentences. This is the change most
       likely to move the score, and the one our corpus size makes
       necessary rather than optional.
